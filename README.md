# Google Form Registration Bot

บอทกรอกและส่ง Google Form อัตโนมัติ เขียนด้วย Java

อ่านคำถามในฟอร์มออกมาให้ดู กรอกคำตอบจากไฟล์ ส่งได้ทั้งคนเดียวและหลายสิบคนรวดเดียว เฝ้ารอฟอร์มที่ยังไม่เปิดได้ และรันซ้ำโดยไม่ส่งซ้ำ

# สิ่งที่ต้องมีก่อน

| อย่าง | เวอร์ชันขั้นต่ำ | เช็กด้วย |
|---|---|---|
| JDK | 21 | `java -version` |
| Apache Maven | 3.9 | `mvn -v` |
| Google Chrome | เวอร์ชันไหนก็ได้ | เปิดโปรแกรมดู |

> Chrome จำเป็นเฉพาะโหมดปกติ — ถ้าใช้ `-Dmode=http` อย่างเดียวไม่ต้องมีก็ได้

> **ไม่ต้องโหลด chromedriver เอง** Selenium หาเวอร์ชันที่ตรงกับ Chrome ในเครื่องมาให้เองตอนรันครั้งแรก

# ติดตั้ง

### 1. JDK

โหลด JDK 21 ขึ้นไปจาก [Adoptium](https://adoptium.net/) แล้วเช็ก `java -version`

### 2. Maven

Maven ไม่มี installer เป็นแค่ zip ที่แตกแล้วชี้ PATH

**Windows**
```powershell
New-Item -ItemType Directory -Force "$HOME\tools" | Out-Null
Invoke-WebRequest -Uri "https://dlcdn.apache.org/maven/maven-3/3.9.16/binaries/apache-maven-3.9.16-bin.zip" -OutFile "$env:TEMP\maven.zip"
Expand-Archive -Path "$env:TEMP\maven.zip" -DestinationPath "$HOME\tools" -Force

$mvnBin = "$HOME\tools\apache-maven-3.9.16\bin"
$old = [Environment]::GetEnvironmentVariable("Path", "User")
if ($old -notlike "*$mvnBin*") {
    [Environment]::SetEnvironmentVariable("Path", "$old;$mvnBin", "User")
}
```

**ปิด PowerShell แล้วเปิดใหม่** (PATH อ่านตอนเปิด process เท่านั้น) แล้วเช็ก `mvn -v`

**macOS** → `brew install maven`
**Linux** → `sudo apt install maven`

### 3. Clone แล้ว build

```bash
git clone https://github.com/<user>/Google-Form-registration-bot.git
cd Google-Form-registration-bot
mvn compile
```

ครั้งแรกช้าเพราะโหลด Selenium (~50MB) ลง `~/.m2/repository` ครั้งต่อไปเร็ว

# เริ่มใช้งาน 4 ขั้น

## ขั้นที่ 1 — ดูก่อนว่าฟอร์มถามอะไร

```bash
mvn -q compile exec:java "-Dform.url=https://docs.google.com/forms/d/e/XXXX/viewform"
```

ยังไม่กรอก ยังไม่ส่ง แค่อ่านออกมาให้ดู

```
กำลังเปิดฟอร์ม...
ฟอร์ม: ลงทะเบียนกิจกรรม

พบคำถาม 4 ข้อ
  [0] ชื่อ-นามสกุล * (SHORT_TEXT)
  [1] อีเมล * (SHORT_TEXT)
  [2] รอบที่ต้องการ (RADIO)
      ตัวเลือก: รอบเช้า | รอบบ่าย
  [3] ความสนใจ (CHECKBOX)
      ตัวเลือก: กีฬา | ดนตรี | ศิลปะ

ยังไม่มีไฟล์คำตอบ (answers.txt) — อ่านอย่างเดียว ไม่ได้กรอกอะไร
```

- `[0]` = เลขข้อ เอาไว้อ้างในไฟล์คำตอบ
- `*` = ข้อที่บังคับตอบ
- `(RADIO)` = ชนิดคำถาม

**เอาชื่อคำถามจากตรงนี้ไปใช้ขั้นต่อไป**

## ขั้นที่ 2 — สร้างไฟล์คำตอบ

สร้าง `answers.txt` ที่ root ของโปรเจกต์ (ระดับเดียวกับ `pom.xml`)

```
# บรรทัดขึ้นต้นด้วย # คือคอมเมนต์
ชื่อ-นามสกุล = สมชาย ใจดี
อีเมล = somchai@example.com
รอบที่ต้องการ = รอบเช้า
ความสนใจ = กีฬา, ดนตรี
```

## ขั้นที่ 3 — ซ้อมกรอก

คำสั่งเดิมกับขั้นที่ 1 เป๊ะ แต่คราวนี้มี `answers.txt` แล้ว

```bash
mvn -q compile exec:java "-Dform.url=..." "-Dheadless=false"
```

`-Dheadless=false` เปิด Chrome ให้เห็นกับตาว่ากรอกถูกช่องไหม

```
กรอกแล้ว: ชื่อ-นามสกุล = สมชาย ใจดี
กรอกแล้ว: อีเมล = somchai@example.com
กรอกแล้ว: รอบที่ต้องการ = รอบเช้า
กรอกแล้ว: ความสนใจ = กีฬา, ดนตรี

กรอกครบแล้วแต่ยังไม่ส่ง (ใส่ "-Dsubmit=true" ถ้าต้องการส่งจริง)
```

## ขั้นที่ 4 — ส่งจริง

```bash
mvn -q compile exec:java "-Dform.url=..." "-Dsubmit=true"
```

⚠️ ส่งแล้วยกเลิกไม่ได้ ต้องเข้าไปลบใน Google Form เอง

# ตัวแปรทั้งหมด

ทุกตัวเป็นรูปแบบ `-Dชื่อ=ค่า` ต่อท้ายคำสั่ง ใส่กี่ตัวก็ได้ ไม่สนลำดับ

| ตัวแปร | ค่าเริ่มต้น | ย่อๆ |
|---|---|---|
| [`form.url`](#formurl) | *(จำเป็น)* | ลิงก์ฟอร์ม |
| [`submit`](#submit) | `false` | กดส่งจริงหรือแค่ซ้อม |
| [`answers`](#answers) | `answers.txt` | ไฟล์คำตอบ 1 คน |
| [`people`](#people) | — | ไฟล์ CSV หลายคน |
| [`mode`](#mode) | `browser` | ใช้ Chrome หรือยิง HTTP ตรง |
| [`threads`](#threads) | `1` | ยิงพร้อมกันกี่สาย |
| [`retry`](#retry) | `3` | ส่งไม่ผ่าน ลองใหม่กี่ครั้ง |
| [`start`](#start) | — | นอนรอจนถึงเวลานี้แล้วค่อยยิง |
| [`schema`](#schema) | `schema.tsv` | ไฟล์จำโครงฟอร์ม |
| [`headless`](#headless) | `true` | ซ่อนหรือโชว์ Chrome |
| [`delay`](#delay) | `5` | เว้นระยะระหว่างคน (วินาที) |
| [`wait`](#wait) | `0` | รอฟอร์มเปิดนานสุดกี่วินาที |
| [`poll`](#poll) | `3` | ระหว่างรอ เช็กทุกกี่วินาที |
| [`results`](#results) | `results.csv` | ไฟล์จดว่าใครส่งแล้ว |

---

### `form.url`

ลิงก์ฟอร์ม **ตัวเดียวที่ขาดไม่ได้** ถ้าไม่ใส่โปรแกรมจะพิมพ์วิธีใช้แล้วจบ

ต้องเป็นลิงก์ที่ลงท้ายด้วย **`/viewform`**

```bash
"-Dform.url=https://docs.google.com/forms/d/e/1FAIpQLSc.../viewform"
```

| ลงท้ายด้วย | ใช้ได้ไหม |
|---|---|
| `/viewform` | ✅ |
| `/closedform` | ❌ เปลี่ยนเป็น `/viewform` เอง บอทเช็กสถานะปิดให้อยู่แล้ว |
| `/edit` | ❌ นั่นคือหน้าแก้ไขฟอร์ม ไม่ใช่หน้ากรอก |

---

### `submit`

**สวิตช์ความปลอดภัยตัวสำคัญที่สุด**

- ไม่ใส่ = กรอกให้ครบแล้วหยุด ไม่ส่ง
- `-Dsubmit=true` = กดส่งจริง

```bash
# ซ้อม — ปลอดภัย ทำกี่รอบก็ได้
mvn -q compile exec:java "-Dform.url=..."

# ส่งจริง
mvn -q compile exec:java "-Dform.url=..." "-Dsubmit=true"
```

ตอนซ้อมจะไม่แตะ `results.csv` เลย ซ้อมกี่รอบก็ไม่ทำให้ข้อมูลจริงเพี้ยน

---

### `answers`

ไฟล์คำตอบสำหรับ **1 คน** รูปแบบ `ชื่อคำถาม = คำตอบ` บรรทัดละข้อ

```bash
"-Danswers=data/somchai.txt"
```

ใช้เก็บหลายชุดแล้วสลับใช้ได้

```bash
mvn -q compile exec:java "-Dform.url=..." "-Danswers=data/somchai.txt" "-Dsubmit=true"
mvn -q compile exec:java "-Dform.url=..." "-Danswers=data/somsri.txt"  "-Dsubmit=true"
```

**การจับคู่ชื่อคำถาม** ทำ 3 ชั้น ตามลำดับ:

| เขียนแบบ | ความหมาย |
|---|---|
| `[0] = สมชาย` | อ้างด้วยเลขข้อ — แม่นที่สุด |
| `ชื่อ-นามสกุล = สมชาย` | ชื่อตรงเป๊ะ |
| `อีเมล = a@b.com` | ชื่อบางส่วน จับคู่กับ `อีเมลของท่าน` ได้ |

ถ้าฟอร์มมีคำถามชื่อซ้ำกัน **ต้องใช้เลขข้อ** ไม่งั้นแยกไม่ออก บอทจะเตือนให้เอง

---

### `people`

ไฟล์ CSV สำหรับส่ง **หลายคนรวดเดียว** ใส่ตัวนี้แล้ว `answers` จะถูกมองข้าม

```bash
"-Dpeople=people.csv"
```

```
[1/20] 1 สมชาย ใจดี
   ส่งแล้ว
[2/20] 2 สมหญิง รักเรียน
   ส่งแล้ว
...
สรุป: สำเร็จ 20 | พลาด 0 | ข้าม 0 | ทั้งหมด 20
```

ถ้าใครพลาด บอทจะไปต่อคนถัดไปไม่หยุดทั้งชุด แล้วสรุปตอนจบว่าพลาดกี่คน

---

### `mode`

เลือกวิธีส่ง

| ค่า | วิธีทำงาน | ความเร็ว (20 คน) |
|---|---|---|
| `browser` *(ค่าเริ่มต้น)* | เปิด Chrome จริง กรอก กดปุ่ม | 54 วิ |
| `http` | ไม่เปิดเบราว์เซอร์ ยิงคำตอบตรง | 21 วิ |

```bash
"-Dmode=http"
```

`http` อ่านคำถามจาก HTML ของหน้าฟอร์มโดยตรง แล้วส่งคำตอบไปที่ปลายทางเดียวกับที่หน้าเว็บใช้ตอนกดปุ่ม Submit

**ข้อแลกเปลี่ยน**
- ไม่รู้จักตัวเลือกของช้อยส์ พิมพ์ผิดจะไม่มีใครเตือน ฟอร์มจะตอบ HTTP error กลับมาแทน
- ไม่มีหน้าจอให้ดู debug ยากขึ้นเวลาฟอร์มเปลี่ยนโครงสร้าง
- ฟอร์มที่มี reCAPTCHA ใช้ไม่ได้

**แนะนำ:** รัน `browser` 1 รอบก่อนเพื่อตรวจว่าคำตอบเข้าถูกช่อง แล้วค่อยสลับมา `http` ตอนยิงจริง

---

### `threads`

ยิงพร้อมกันกี่สาย **ใช้ได้เฉพาะ `-Dmode=http`**

```bash
"-Dthreads=4"
```

เวลาเกือบทั้งหมดคือนั่งรอ Google ตอบ พอยิงหลายสายการรอจะทับซ้อนกัน เลยเร็วขึ้นเกือบเป็นเท่าตัว

**วัดจริง 20 คน**

| จำนวนสาย | เวลา |
|---|---|
| 1 | 13.7 วิ |
| 4 | 5.2 วิ |
| 8 | 3.7 วิ |

ตรวจแล้วว่าทั้ง 3 แบบได้ `results.csv` ครบ 20 แถว ไม่ซ้ำไม่ตกหล่น

**สิ่งที่เปลี่ยนไปเมื่อใช้หลายสาย**
- บรรทัดที่พิมพ์ออกมาจะไม่เรียงตามลำดับแถว
- `-Ddelay` กลายเป็นระยะห่างของการ*ปล่อย*งาน ไม่ใช่ระยะห่างระหว่างคนที่ส่งจริง
- จำกัดไว้สูงสุด 16 สาย ขอมากกว่านั้นจะถูกตัดลงให้

> ⚠️ **การยิงหลายสายพร้อมกันจากไอพีเดียวไปฟอร์มเดียว เป็นรูปแบบที่ผิดปกติที่สุดในสายตาผู้ให้บริการ** ต่างจากการเร่งด้วย `mode=http` ที่แค่ตัดงานเปล่าประโยชน์ทิ้ง ชั่งดูก่อนใช้ว่าคุ้มไหม
>
> ถ้าจะใช้ แนะนำ 4 สายก็เกินพอ — จาก 4 ไป 8 ได้เพิ่มมาแค่ 1.5 วินาที

---

### `retry`

ถ้าส่งไม่ผ่าน ให้ลองใหม่กี่ครั้ง (เว้น 1 วินาทีระหว่างครั้ง)

```bash
"-Dretry=5"
```

ค่าเริ่มต้น 3 ครั้ง `-Dretry=1` = ไม่ลองใหม่เลย

**มีไว้ทำไม** — ฟอร์มที่เพิ่งเปลี่ยนจากปิดเป็นเปิด ปลายทางอาจปฏิเสธคำตอบอยู่ช่วงสั้นๆ ทำให้การรันแบบเฝ้ารอ **ผ่านบางคนพลาดบางคน** ทั้งที่ข้อมูลถูกหมด

ถ้ามีการลองใหม่ จะเห็นในผลลัพธ์:
```
[2/20] ... — ครั้งที่ 1 ไม่ผ่าน (ฟอร์มตอบกลับ HTTP 400) ลองใหม่
[2/20] ... — ส่งแล้ว (ลอง 2 ครั้ง)
```

---

### `start`

นอนรอจนถึงเวลาบนนาฬิกาแล้วค่อยเริ่มยิง

```bash
"-Dstart=00:00:00"
```

รับทั้ง `HH:mm` และ `HH:mm:ss`

**การรอเกิดขึ้นก่อนทุกอย่าง** — ก่อนแตะฟอร์มด้วยซ้ำ ไม่งั้นเวลาที่นัดไว้จะไหลผ่านไปตอนกำลังโหลดหน้าเว็บ

**ถ้าเวลาผ่านไปแล้ว บอทจะเริ่มทันที ไม่รอข้ามวัน**

```
เลยเวลา 22:19:10 มา 20 วินาทีแล้ว — เริ่มทันที
```

การพลาดรอบลงทะเบียนเสียหายกว่าการยิงช้าไปหน่อยมาก จะรอถึงพรุ่งนี้ก็ต่อเมื่อเวลานั้นผ่านมาแล้ว **เกิน 12 ชั่วโมง** เท่านั้น — ท่าตั้ง `-Dstart=00:00:00` ตอนสี่ทุ่มจึงยังทำงานถูก

**ต่างจาก `-Dwait` ยังไง**

| | ทำอะไร |
|---|---|
| `-Dstart` | นอนรอเฉยๆ จนถึงเวลาที่นัด ไม่รบกวนเซิร์ฟเวอร์เลย |
| `-Dwait` | หลังเริ่มแล้ว ถ้าฟอร์มยังไม่รับ ให้พยายามต่อนานสุดกี่วินาที |

ใช้คู่กันคือท่ามาตรฐานสำหรับฟอร์มที่เปิดตรงเวลา — เปิดโปรแกรมทิ้งไว้ล่วงหน้า มันจะนอนรอเงียบๆ แล้วยิงพรึ่บตอนเที่ยงคืนพอดี

### `schema`

ไฟล์ที่บอทจดโครงฟอร์มไว้ (ชื่อคำถาม + `entry.NNN` ของแต่ละช่อง)

**ปกติไม่ต้องใส่** — บอทตั้งชื่อไฟล์ตาม id ของฟอร์มให้เอง เช่น

```
schema-1FAIpQLScFFE_CLMpRX89ipT__IkGZNQ_TPlLfuL7-ggbC1Vfpiy9Xuw.tsv
```

**ทำงานกับหลายฟอร์มพร้อมกันได้เลย** แต่ละใบมีไฟล์ของตัวเอง ไม่ปนกัน

ข้างในไฟล์มีบรรทัด `# form: <id>` กำกับไว้ ถ้าเอาไฟล์ของฟอร์มอื่นมาใช้ผิดใบ บอทจะปฏิเสธแทนที่จะยิงมั่ว:

```
ไฟล์ schema-xxx.tsv เป็นโครงของฟอร์มอื่น (yyy) จะไม่ใช้
```

> **สำคัญ:** `entry.NNN` เป็นของเฉพาะฟอร์มใบนั้น ต่อให้ 3 ฟอร์มมีคำถามเหมือนกันทุกตัวอักษร เลขก็คนละชุด — ใช้ schema ผิดใบ = ส่งไม่เข้าเลยทั้งชุด

จะกำหนดเองก็ได้:
```bash
"-Dschema=schema-รอบเช้า.tsv"
```

**ทำไมถึงสำคัญกับความเร็ว** — ฟอร์มที่ยังไม่เปิดจะไม่แสดงคำถามเลย บอทเลยส่งอะไรไม่ได้จนกว่าจะโหลดหน้าเว็บมาอ่านก่อน ซึ่งกินเวลาราว 1 วินาที **หลัง**ฟอร์มเปิดไปแล้ว

ถ้ามีไฟล์นี้อยู่ บอทข้ามขั้นตอนอ่านหน้าเว็บทั้งหมด ยิงได้ทันทีที่ถึงเวลา

บอทเขียนไฟล์นี้ให้เองทุกครั้งที่อ่านฟอร์มสำเร็จ — **รันซ้อม 1 รอบตอนฟอร์มเปิดอยู่ก็ได้ไฟล์แล้ว**

```bash
# ตอนฟอร์มยังเปิด รันอันนี้ 1 ครั้งเพื่อเก็บโครงไว้
mvn -q compile exec:java "-Dform.url=<URL>" "-Dmode=http"
```

> ⚠️ **ถ้าเจ้าของฟอร์มแก้คำถามหลังจากนั้น ต้องลบไฟล์นี้ทิ้งแล้วเก็บใหม่** ไม่งั้นบอทจะยิงไปที่ช่องเก่าที่ไม่มีแล้ว

---

### `headless`

ซ่อนหรือโชว์หน้าต่าง Chrome (มีผลเฉพาะ `mode=browser`)

```bash
"-Dheadless=false"    # โชว์ให้เห็นกับตา
```

ค่าเริ่มต้นคือซ่อน เพราะเร็วกว่า ใส่ `false` ตอนอยากตรวจว่ากรอกถูกช่องไหม

---

### `delay`

เว้นระยะกี่วินาทีระหว่างแต่ละคน (ใช้กับ `people` เท่านั้น)

```bash
"-Ddelay=0"     # เร็วสุด ไม่เว้นเลย
"-Ddelay=10"    # เว้น 10 วิ
```

ค่าเริ่มต้น 5 วินาที — `-Ddelay=0` ประหยัดไปได้เกือบนาทีเมื่อส่ง 20 คน

---

### `wait`

ถ้าฟอร์มยังไม่เปิด ให้เฝ้ารอนานสุดกี่วินาที

```bash
"-Dwait=1800"    # รอไม่เกิน 30 นาที
```

```
รอฟอร์มเปิด (รอไม่เกิน 1800 วิ, เช็กทุก 5 วิ)
  ครั้งที่ 1: ยังปิดอยู่ รออีก 5 วิ
  ครั้งที่ 2: ยังปิดอยู่ รออีก 5 วิ
ฟอร์มเปิดแล้ว
```

ค่าเริ่มต้น `0` = ไม่รอ เจอฟอร์มปิดก็จบเลย

⚠️ **นับเวลาจากตอนกดรัน ไม่ใช่นัดเวลาล่วงหน้า** — ฟอร์มเปิด 9 โมง ต้องมากดรันเองสัก 8:55

---

### `poll`

ระหว่างรอ ให้เช็กซ้ำทุกกี่วินาที ใช้คู่กับ `wait`

```bash
"-Dwait=1800" "-Dpoll=5"
```

ค่าเริ่มต้น 3 วินาที **อย่าตั้งถี่กว่านี้** ไม่ได้ช่วยอะไรและเป็นการรบกวนเซิร์ฟเวอร์เปล่าๆ

---

### `results`

ไฟล์ที่บอทจดว่าใครส่งสำเร็จไปแล้ว (ใช้กับ `people` เท่านั้น)

```bash
"-Dresults=results-รอบเช้า.csv"
```

**นี่คือระบบกันส่งซ้ำ** — จดทันทีทีละคน ไม่ใช่ตอนจบ เน็ตหลุดกลางคันแล้วรันคำสั่งเดิมซ้ำ บอทจะข้ามคนที่ส่งไปแล้ว

```
[1/20] 1 สมชาย ใจดี — ส่งไปแล้ว ข้าม
...
สรุป: สำเร็จ 0 | พลาด 0 | ข้าม 20 | ทั้งหมด 20
```

อยากยิงชุดเดิมใหม่ทั้งหมด ให้ **ลบไฟล์นี้ทิ้ง**

---

# สูตรสำเร็จ

### สำรวจฟอร์มครั้งแรก
```bash
mvn -q compile exec:java "-Dform.url=<URL>"
```

### ซ้อม 1 คน แบบเห็นหน้าจอ
```bash
mvn -q compile exec:java "-Dform.url=<URL>" "-Dheadless=false"
```

### ส่งจริง 1 คน
```bash
mvn -q compile exec:java "-Dform.url=<URL>" "-Dsubmit=true"
```

### ซ้อมทั้ง 20 คน
```bash
mvn -q compile exec:java "-Dform.url=<URL>" "-Dpeople=people.csv"
```

### ส่งจริง 20 คน
```bash
mvn -q compile exec:java "-Dform.url=<URL>" "-Dpeople=people.csv" "-Dsubmit=true"
```

### ⚡ เร็วที่สุด — 20 คนใน 16 วินาที

สร้าง jar ครั้งเดียว:
```bash
mvn package
```

แล้วยิง:
```bash
java "-Dform.url=<URL>" "-Dmode=http" "-Dpeople=people.csv" "-Dsubmit=true" "-Ddelay=0" -jar target/form-bot.jar
```

> ⚠️ `-D` ทุกตัวต้องอยู่ **ก่อน** `-jar` ถ้าไปไว้หลังจะกลายเป็น argument ธรรมดา ค่าไม่ถึงโปรแกรม

### 🎯 ฟอร์มเปิดตรงเวลา — ให้ลงภายใน 1 วินาที

**เตรียมล่วงหน้า** (ทำตอนฟอร์มยังเปิดอยู่ ครั้งเดียวพอ) เพื่อเก็บโครงฟอร์มไว้:
```bash
mvn -q compile exec:java "-Dform.url=<URL>" "-Dmode=http"
```

**เปิดโปรแกรมทิ้งไว้ก่อนถึงเวลา** แล้วมันจะยิงเองตอนเที่ยงคืนพอดี:
```bash
java "-Dform.url=<URL>" "-Dmode=http" "-Dpeople=people.csv" "-Dsubmit=true" "-Ddelay=0" "-Dthreads=5" "-Dstart=00:00:00" "-Dwait=120" -jar target/form-bot.jar
```

| ตัวเลือก | หน้าที่ |
|---|---|
| `-Dstart=00:00:00` | นอนรอเงียบๆ จนถึงเวลา ไม่ยิงก่อน |
| `-Dthreads=5` | 5 คนออกพร้อมกันหมด ไม่ต้องรอคิว |
| `-Ddelay=0` | ไม่เว้นจังหวะ |
| `-Dwait=120` | ถ้าฟอร์มยังไม่รับ ให้พยายามซ้ำถี่ๆ (ทุก 0.25 วิ) นานสุด 2 นาที |
| มี `schema.tsv` | ข้ามการโหลดหน้าเว็บ ประหยัดไปอีก ~1 วินาที |

### รอฟอร์มเปิดแบบไม่รู้เวลาแน่นอน
```bash
java "-Dform.url=<URL>" "-Dmode=http" "-Dpeople=people.csv" "-Dsubmit=true" "-Ddelay=0" "-Dwait=1800" "-Dpoll=3" -jar target/form-bot.jar
```

### เทียบเวลา (20 คน วัดจริง)

| วิธี | เวลา |
|---|---|
| Chrome + Maven | 54 วิ |
| `-Dmode=http` + Maven | 21 วิ |
| `-Dmode=http` + jar | 14 วิ |
| + `-Dthreads=4` | 5.2 วิ |
| + `-Dthreads=8` | **3.7 วิ** |

คำสั่งของแถวสุดท้าย:

```bash
java "-Dform.url=<URL>" "-Dmode=http" "-Dpeople=people.csv" "-Dsubmit=true" "-Ddelay=0" "-Dthreads=8" -jar target/form-bot.jar
```

อ่านข้อควรระวังของการยิงหลายสายที่หัวข้อ [`threads`](#threads) ก่อนใช้

# แก้ปัญหาที่เจอบ่อย

### ภาษาไทยออกมาเป็น `α╕úα╕¡α╕ƒ`

console ตีความ byte ผิดชุดตัวอักษร ไม่ใช่บั๊ก และ**ไม่กระทบข้อมูลที่ส่งเข้าฟอร์มเลย**

สั่ง 2 บรรทัดนี้ก่อน 1 ครั้งต่อการเปิด terminal:
```powershell
chcp 65001
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

อยากให้ถาวร ใส่ไว้ใน PowerShell profile:
```powershell
if (-not (Test-Path $PROFILE)) { New-Item -ItemType File -Path $PROFILE -Force | Out-Null }
Add-Content -Path $PROFILE -Value "[Console]::OutputEncoding = [System.Text.Encoding]::UTF8" -Encoding utf8
```

macOS/Linux เป็น UTF-8 อยู่แล้ว ไม่ต้องทำอะไร

### ค่า `-D` ไม่มีผล บน PowerShell

ต้องครอบด้วย double quote **ทุกตัว**

```powershell
mvn -q compile exec:java "-Dform.url=..." "-Dsubmit=true"
```

ไม่ครอบ PowerShell จะแย่ง `-D` ไปตีความเป็น parameter ของตัวเอง บน bash/cmd ไม่ต้องครอบ

### `Unable to access jarfile target\form-bot.jar`

ยังไม่ได้สร้าง jar บนเครื่องนั้น — `target/` เป็นผลลัพธ์ build ไม่ได้ commit ขึ้น git

```bash
mvn package
```

### เครื่องที่เพิ่ง clone มาต้องเตรียม 3 อย่าง

ทั้งหมดอยู่ใน `.gitignore` จึงไม่ติดมากับ git

| ไฟล์ | ได้มายังไง |
|---|---|
| `target/form-bot.jar` | `mvn package` |
| `people.csv` | สร้างเอง หัวตารางต้องตรงกับชื่อคำถามในฟอร์ม |
| `schema.tsv` | ก๊อปจากเครื่องเดิม หรือรัน `mvn -q compile exec:java "-Dform.url=<URL>" "-Dmode=http"` ตอนฟอร์มเปิด |

เช็กก่อนรันจริง:
```powershell
Test-Path target\form-bot.jar, schema.tsv, people.csv
```

### `'mvn' is not recognized`

Maven ยังไม่อยู่ใน PATH หรือยังไม่ได้เปิด terminal ใหม่หลังติดตั้ง

### `ฟอร์มยังไม่เปิดรับคำตอบ`

ฟอร์มปิดอยู่จริง ไม่ใช่บอทพัง — ใส่ `-Dwait=1800` ถ้าอยากให้เฝ้ารอจนเปิด

### `ไม่พบคำถามในหน้านี้`

ลิงก์ไม่ใช่หน้ากรอกฟอร์ม ต้องลงท้าย `/viewform` ไม่ใช่ `/edit` — หรือฟอร์มบังคับล็อกอิน

### `ไม่ได้กรอกอะไรเลย`

ชื่อคำถามในไฟล์คำตอบไม่ตรงกับในฟอร์ม รันขั้นที่ 1 ดูชื่อจริงแล้วก๊อปมาใส่

### `คำถาม "..." ไม่มีตัวเลือก "..."`

พิมพ์ช้อยส์ไม่ตรง ระวังช่องว่างเกินหรือวรรณยุกต์ ดูรายการตัวเลือกที่บอทบอกมาแล้วก๊อปไปวาง

### รันแล้วข้ามทุกคน `ข้าม 20`

`results.csv` จดไว้ว่าส่งไปแล้ว ลบไฟล์นั้นทิ้งถ้าอยากยิงชุดเดิมใหม่

```bash
rm results.csv
```
